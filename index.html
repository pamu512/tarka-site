What defines Tarka

Two things, on purpose.

Audit everything.

Every evaluate and every human override has a receipt. If a human changes a decision, Tarka stores why. The override becomes a label the pack can learn from. The optional copilot (Advise) drafts and explains; it never decides. Receipts land on /decisions with in-context pack-why.

Review is the exception.

Investigation is a residual station born from evaluate → deny or review. ALLOW never becomes a case. When review happens, there is a feedback loop straight back into the packs, not a growing ticket queue.

The journey, not payments

Progressive friction from signup onward.

These are the pack-evaluation points you wire, not prebuilt journey screens. At each hop: allow, step-up, review, or block. Each event heats the next. Skipping or avoiding a risk check doesn't block. It raises showing-signs risk.

Login

Credential and device signals at the door. Known-good devices pass quietly.

Device

The device is a node, not the person. ATO victims stay good entities.

Onboarding

proven / already-risky / showing-signs / unknown: entity states, never a flat device flag.

Payment

Packs evaluate the transaction; receipts record the why. Chargeback is one late label, not the product.

Payout

The last mile: enforcement is contract-gated and emit-only by default: advisory, never a silent block.

The stack

Evaluate stays Rust. The rest is optional.

EvaluateRust · core

Decide

decision-api owns allow / deny / flag / review: Rust JSON packs via the rule engine. Deterministic, replayable, no Tarka-branded model ever decides.

DeskReact app

Hunt

First receipt lands on /decisions with pack-why. ALLOW never opens a case. Residual work is review/deny leftovers, worked on Hunt at depth-1, and only when the graph plane is configured.

Observe / AdviseOptional

Learn

Observe runs packs in shadow with promote gates. Humans Promote, never auto. Advise is a BYO-LLM copilot for investigations. Empty URL means the plane is simply off.
